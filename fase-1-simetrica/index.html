01 Criptografia simétrica

Uma chave encripta e a mesma chave decripta. Aqui a chave nasce de uma password. Escreve à esquerda, lê à direita o que está a acontecer. Material educativo: não uses isto para proteger dados reais.

AEntrada

BPacote (versão.salt.iv.cifrado, em base64)

CDetalhes

Ainda sem dados. Carrega em Encriptar.

DResultado


      

    


    
    

      
Passo a passo

      
    

        
  1. 
          
    Escolhe o texto e a password
    
          
    
            
    Escreve qualquer texto no campo Texto e uma password no campo Password. A password é o único segredo desta fase. A chave não é guardada em lado nenhum: quem souber a password consegue refazê-la, e quem não souber não tem nada.
    
            
    Por dentroA password não serve diretamente como chave. O AES-256 precisa de 32 bytes aleatórios e uma password tem poucos caracteres previsíveis. O passo seguinte resolve isso.
    
          
    
        
    2. 

        
  2. 
          
    Carrega em Encriptar
    
          
    
            
    O browser faz quatro coisas, por esta ordem:
    
            
      
              
    1. Primeiro o salt: 16 bytes aleatórios. Não é secreto e vai dentro do pacote. Serve para a mesma password dar uma chave diferente de cada vez.
      2. 
              
    2. Depois a chave: o PBKDF2 mistura a password com o salt 600 000 vezes (SHA-256) e produz a chave AES de 256 bits. As repetições tornam cada tentativa lenta, e isso pesa muito a quem testa passwords às centenas de milhar.
      3. 
              
    3. Em seguida o IV, 12 bytes aleatórios, novos em cada mensagem. Nunca se pode repetir com a mesma chave (a fase 5 mostra o desastre).
      4. 
              
    4. Por fim o AES-GCM cifra o texto e calcula uma etiqueta de 16 bytes que garante que ninguém mexeu nos dados. A etiqueta fica colada ao fim do cifrado.
      5. 
            
    
            
    const salt  = crypto.getRandomValues(new Uint8Array(16));
const chave = await derivarChave(password, salt); // PBKDF2 → AES-256
const iv    = crypto.getRandomValues(new Uint8Array(12));
const cifrado = await crypto.subtle.encrypt(
  { name: "AES-GCM", iv }, chave, texto);
    
          
    
        
    3. 

        
  3. 
          
    Lê o pacote
    
          
    
            
    O pacote tem quatro partes separadas por pontos: a versão do formato, o salt, o IV e o cifrado. Está em base64, que é só uma maneira de escrever bytes como texto copiável. O base64 não protege nada.
    
            
    Quem recebe o pacote precisa dele inteiro mais a password. O salt e o IV viajam à vista, e isso não faz mal, porque o segredo é a password. Os valores desta encriptação:
    
            
    
              
    Salt (16 bytes, hex)
    
              
    (carrega em Encriptar)
    
              
    IV (12 bytes, hex)
    
              
    (carrega em Encriptar)
    
              
    Texto cifrado (hex)
    
              
    (carrega em Encriptar)
    
              
    Etiqueta GCM (16 bytes, hex)
    
              
    (carrega em Encriptar)
    
            
    
            
    ExperimentaEncripta o mesmo texto outra vez. O salt, o IV e todo o cifrado mudam, apesar de o texto e a password serem iguais.
    
          
    
        
    4. 

        
  4. 
          
    Carrega em Decriptar
    
          
    
            
    O caminho inverso. O browser lê o salt do pacote, refaz a chave com a mesma password e pede ao AES-GCM para decifrar. Antes de devolver o texto, o GCM recalcula a etiqueta e compara com a que veio no pacote. Só se coincidirem é que sai o texto.
    
            
    const claro = await crypto.subtle.decrypt(
  { name: "AES-GCM", iv }, chave, cifrado);
    
            
    ExperimentaMuda uma letra da password e decripta. Falha. Com a password errada a chave é outra, a etiqueta não bate certo e o GCM recusa.
    
          
    
        
    5. 

        
  5. 
          
    Altera 1 byte e decripta outra vez
    
          
    
            
    O botão inverte um bit do primeiro byte do cifrado, como se alguém tivesse mexido no pacote pelo caminho. Carrega em Decriptar a seguir: falha, e não devolve texto estragado.
    
            
    Por dentroEsta é a diferença entre cifrar e cifrar com autenticação. Numa cifra sem etiqueta (o CBC, por exemplo), a alteração passava sem aviso e o texto saía corrompido. O erro é o mesmo para password errada e para dados alterados, de propósito: não dá pistas a quem ataca.

Em resumo

      
A chave são os 32 bytes que o AES usa para cifrar e decifrar, e aqui nascem da password. O salt e o IV são bytes aleatórios e públicos, o primeiro misturado com a password antes de fazer a chave e o segundo diferente em cada mensagem. A etiqueta GCM são os 16 bytes finais que provam que o cifrado não foi alterado. O base64 só escreve bytes como letras e números e não cifra nada.
