Passo a passo

      
    

        
  1. 
          
    Gera um par de chaves RSA
    
          
    
            
    Carrega em Gerar par RSA-3072. O browser cria duas chaves matematicamente ligadas. A pública pode ser dada a toda a gente (está no campo acima). A privada fica só contigo.
    
            
    Porquê 3072 bits? Segundo o NIST (SP 800-57), RSA-3072 dá cerca de 128 bits de segurança, o mesmo que AES-128. Uma chave RSA de 3072 bits protege tanto como uma AES de 128, não como uma de 3072. Para chegar ao nível do AES-256 o RSA precisaria de 15 360 bits.
    
            
    const par = await crypto.subtle.generateKey(
  { name: "RSA-OAEP", modulusLength: 3072,
    publicExponent: new Uint8Array([1,0,1]), hash: "SHA-256" },
  false, ["encrypt", "decrypt"]); // false: privada não extraível
    
            
    
              
    Tempo a gerar
    (carrega em Gerar)
    
              
    Chave pública
    (carrega em Gerar)
    
              
    A privada é extraível?
    (carrega em Gerar)
    
            
    
            
    Por dentroO browser guarda a privada internamente e o teu JavaScript não consegue ler os bytes dela, por isso não há botão para a mostrar. Se uma página tiver uma falha, quem a explorar não consegue copiar a chave (continua a poder pedir ao browser para a usar enquanto a página estiver aberta). Em geral, gera as privadas com extractable: false sempre que não precisares de as guardar.

  2. 
          
    Encripta com a pública
    
          
    
            
    Escreve um texto curto e carrega em Encriptar com a pública. Qualquer pessoa com a chave pública pode fazer isto. Só quem tem a privada consegue desfazer.
    
            
    
              
    Texto claro
    (carrega em Encriptar)
    
              
    Cifrado
    (carrega em Encriptar)
    
              
    Início do cifrado (hex)
    (carrega em Encriptar)
    
            
    
            
    Por dentroO RSA puro seria previsível (o mesmo texto daria sempre o mesmo cifrado). O OAEP acrescenta bytes aleatórios e uma máscara antes da conta RSA. Por isso encriptar duas vezes o mesmo texto dá cifrados diferentes. Experimenta.
    
          
    
        
    3. 

        
  3. 
          
    Decripta com a privada
    
          
    
            
    O caminho inverso. Se mexeres numa letra do campo Cifrado e decriptares, falha: o OAEP deteta que o conteúdo não tem a estrutura certa.
    
            
    const claro = await crypto.subtle.decrypt(
  { name: "RSA-OAEP" }, par.privateKey, cifrado);
    
          
    
        
    4. 

        
  4. 
          
    Tenta encriptar 400 bytes
    
          
    
            
    O RSA só encripta blocos pequenos. Com uma chave de 384 bytes (3072 bits), o OAEP usa 2 × 32 bytes do hash SHA-256 e mais 2 bytes de estrutura, sobrando 384 − 64 − 2 = 318 bytes. Carrega em Tentar 400 bytes para ver o erro.
    
            
    
              
    Limite
    (carrega no botão)
    
              
    Erro do browser
    (carrega no botão)
    
            
    
            
    Por dentroE mesmo dentro do limite o RSA é lento (milhares de vezes mais que o AES). Esta limitação, mais a lentidão, é a razão da fase 3: usar o RSA para proteger uma pequena chave AES e o AES para a mensagem.
    
          
    
        
    5. 

        
  5. 
          
    Gera um par de chaves para assinar
    
          
    
            
    Encriptar e assinar são coisas diferentes e usam-se pares de chaves diferentes (é boa prática, e a Web Crypto até a impõe: uma chave RSA-OAEP só pode encriptar, não assinar). Aqui usamos ECDSA na curva P-256, que dá cerca de 128 bits de segurança com chaves de 256 bits.
    
            
    Numa assinatura o sentido inverte-se: assinas com a privada, qualquer pessoa verifica com a pública.
    
            
    Chave pública
    (carrega em Gerar par ECDSA)
    
            
    Por dentroA chave RSA ocupa 422 bytes na forma pública, a ECDSA cerca de 91. Para a mesma segurança as curvas elípticas são muito mais compactas. Com extractable: false a privada nunca sai do browser, mas a pública exporta-se sempre.
    
          
    
        
    6. 

        
  6. 
          
    Assina um texto
    
          
    
            
    A assinatura é calculada sobre um resumo (hash SHA-256) do texto, com a chave privada. Prova duas coisas: o texto não foi alterado e foi quem tem a privada que o assinou.
    
            
    const sig = await crypto.subtle.sign(
  { name: "ECDSA", hash: "SHA-256" }, privada, texto);
    
            
    Tamanho da assinatura
    (carrega em Assinar)
    
            
    AtençãoAssinar não esconde o texto. Qualquer pessoa o lê. Para o esconder, encripta-se (e normalmente faz-se as duas coisas).
    
          
    
        
    7. 

        
  7. 
          
    Verifica a assinatura
    
          
    
            
    Com a chave pública e o mesmo texto, verify devolve true. Não revela nenhum segredo: é por isso que qualquer pessoa pode verificar.
    
          
    
        
    8. 

        
  8. 
          
    Altera 1 letra e verifica outra vez
    
          
    
            
    O botão muda a primeira letra do texto e verifica de novo com a assinatura antiga. Dá inválida: bastou 1 letra para o resumo mudar por completo. É assim que se sabe que um documento assinado foi adulterado.
    
            
    ExperimentaAssina, apaga a assinatura e escreve outra qualquer em base64 do mesmo tamanho. Também falha. Sem a privada não há forma prática de fabricar uma assinatura válida.

    10. 
      


      
Em resumo

      
Um par de chaves tem uma pública (para partilhar) e uma privada (para guardar). Encriptar com a pública só se desfaz com a privada. Assinar com a privada verifica-se com a pública. O RSA só aguenta mensagens pequenas, por isso encripta chaves e não ficheiros.
